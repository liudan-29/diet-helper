# 饮食小助手产品路线图

## 为什么有这份文档

饮食小助手最终不是只有“去哪吃”。当前为了验证核心需求，先做范围较小的 MVP。暂时不进入 MVP 的功能统一记录在这里，避免后续误当成已取消。

## 完整产品设想

课件成品展示了六类页面或核心界面：

1. 登录
2. 去哪吃
3. 自己做
4. 记一笔
5. 我的
6. 餐厅卡

其中“餐厅卡”是“去哪吃”里的核心浏览组件，不作为底部独立导航。

## 当前 MVP：只验证“去哪吃”

### 保留功能

- 获取当前位置，定位失败时允许手动选择地点
- 选择早餐、午餐、晚餐或夜宵
- 选择日常、请客、一个人、清淡等用餐场景
- 设置人均预算
- 通过高德 MCP 查询附近真实餐厅
- 按营业状态、餐次、场景、预算和距离筛选
- 展示餐厅卡片、推荐理由和多张图片
- 换一家、补充候选餐厅
- 打开高德导航
- 记录查看、跳过、选择、导航和不合适反馈

### MVP 暂缓功能

| 功能 | 当前处理 | 暂缓原因 | 重新评估条件 |
|---|---|---|---|
| 登录 | 不展示 | 一次用餐决策不需要账号 | 需要跨设备同步或长期保存时 |
| 自己做 | 不展示 | 属于另一条“在家做饭”任务链 | “去哪吃”验证通过，并明确自己做的具体场景后 |
| 记一笔 | 不展示 | 属于长期饮食记录，不影响当次选择 | 用户持续使用后，出现记录与复盘需求时 |
| 我的 | 不展示 | 当前没有账号和长期个人数据 | 需要管理忌口、口味、预算和历史时 |
| 长期餐厅收藏 | 不开发 | MVP 只验证当次推荐 | 用户反复提出收藏或再次访问需求时 |
| 原生 APP / 小程序 | 不开发 | 网页足以完成首轮测试 | 网页留存和使用频率证明有独立入口价值时 |

## 后续功能的已知方向

以下功能名称已确定，但细节还需要单独拆解，不能直接按猜测开发。

### 自己做

- 目标：用户不想外出时，帮助决定在家做什么。
- 待确认：按现有食材、做饭时间、厨具还是饮食目标生成方案。

### 记一笔

- 目标：记录已经吃过的内容。
- 待确认：只记餐厅与菜品，还是同时记录金额、营养和感受。

### 我的

- 目标：管理长期个人信息。
- 待确认：是否包含忌口、过敏、口味、预算、常用地点、收藏和历史记录。

### 登录

- 目标：支持长期数据和跨设备同步。
- 待确认：手机号、微信还是其他登录方式；MVP 阶段不选择。

## 功能恢复原则

1. 先完成“去哪吃”真实数据闭环。
2. 用实际反馈确认用户下一步最需要什么。
3. 每次只恢复一条完整任务链，不同时铺开多个空页面。
4. 恢复功能时重新写功能拆解和验收标准。

## 当前状态

- “去哪吃”：进入 MVP 开发拆解。
- 登录、自己做、记一笔、我的：已记录，暂缓，不是取消。
