# 去哪吃功能拆解与验收标准

## B1：实体生命周期

### 显性实体

显性实体沿用结构文档中的用餐需求、餐厅快照、推荐结果和用户反馈。

#### 用餐需求

```text
编辑中
  → 已定位
  → 查询中
      → 已返回结果
          → 已选择餐厅
          → 已放弃
      → 无结果
          → 扩大范围后重新查询
      → 查询失败
          → 重试
```

牵连关系：

- 进入查询中时创建高德查询任务。
- 查询成功时生成餐厅快照和推荐结果。
- 查询失败或超时时保留位置、餐次、场景和预算。
- 选择一家餐厅后，未展示的推荐结果标记为过期。
- 重新开始时创建新的用餐需求，旧需求停止追加推荐。

#### 餐厅快照

```text
已创建 → 已标准化 → 已参与筛选
                    → 进入推荐
                    → 被过滤
```

牵连关系：

- 快照只属于一次用餐需求，创建后不修改。
- 高德数据后续变化不回写旧快照。
- 删除用餐需求时，其快照随用餐需求删除。

#### 推荐结果

```text
已生成
  → 被过滤
  → 进入候选
      → 已展示
          → 被跳过
          → 被选择
      → 已过期
```

牵连关系：

- 被选择时，用餐需求进入已选择餐厅。
- 用户换一家时，当前推荐进入被跳过，下一条候选进入已展示。
- 候选数量降到补充阈值时，创建新的高德查询任务，但不重置浏览位置。

#### 用户反馈

```text
已产生 → 已记录
       → 记录失败 → 重试
```

牵连关系：

- 查看、跳过、选择和导航由系统自动产生。
- 不合适原因由用户主动选择。
- 反馈失败不阻塞换一家或打开导航。

### 隐性实体

#### 匿名会话

```text
已创建 → 使用中 → 已过期
```

- 浏览器首次打开产品时创建匿名会话标识。
- 同一浏览器有效期内的用餐需求归入同一匿名会话。
- 会话过期后，历史测试数据保留用于聚合统计，但前端不恢复旧流程。

#### 高德查询任务

```text
已创建 → 查询中 → 已成功
                 → 已失败 → 创建重试任务
                 → 已超时 → 创建重试任务
                 → 已取消
```

- 一次任务只对应一次明确的高德MCP调用。
- 成功任务保存调用参数、完成时间和返回数量，不保存密钥。
- 重试创建新任务并关联原任务，不能覆盖原失败记录。
- 相同用餐需求的重复提交使用幂等标识，避免并发生成重复结果。

#### 推荐规则版本

```text
待启用 → 使用中 → 已停用
```

- 每次用餐需求固定记录一个规则版本。
- 规则更新只影响新需求，旧推荐结果不重新计算。
- 同一时刻只能有一个默认使用的规则版本。

### 不单独建模的内容

- 候选餐厅池由推荐结果的状态表示，不另建重复数据。
- 定位是用餐需求的输入和属性，不另建地点对象。
- 导航是推荐结果的转化动作，不另建导航对象。
