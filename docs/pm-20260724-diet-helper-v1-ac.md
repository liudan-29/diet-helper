# 饮食小助手正式初版功能拆解与验收标准

## B1：实体生命周期与牵连

### 用户资料

状态机见结构文档。资料修改后，只影响新建的外出用餐需求和做饭方案默认值，不回写已经保存的历史记录。清除全部数据时，所有本地对象和照片一起删除。

### 外出用餐需求、餐厅和推荐结果

状态机沿用结构文档与`pm-20260724-where-to-eat-ac.md`。选中餐厅后可以创建收藏或预填饮食记录。取消收藏不影响推荐历史和饮食记录。

### 做饭方案

状态机见结构文档。方案生成后可以收藏或创建饮食记录。删除方案时，已经生成的饮食记录保留标题和摘要，不再依赖原方案。

### 饮食记录

状态机见结构文档。删除先进入软删除状态，撤销时恢复；撤销窗口结束后删除关联照片。修改记录不回写餐厅快照和做饭方案。

### 隐性实体

#### 本地数据仓库

```text
未初始化 → 可用
         → 读取失败 → 恢复空状态并保留损坏备份
         → 写入失败 → 保留页面输入并提示用户
```

#### 图片仓库

```text
待处理 → 压缩中 → 已保存
                 → 处理失败 → 允许重新选择
已保存 → 被记录引用 → 记录永久删除后清理
```

#### 数据结构版本

```text
当前版本 → 检测到旧版本 → 迁移成功
                         → 迁移失败 → 保留旧数据并停止覆盖
```

## B2：五个必问

### Q1：空状态

- 首次进入去哪吃时显示完整条件表单
- 首次进入自己做时显示食材、时间、人数和厨具输入
- 没有饮食记录时显示新建第一条记录入口
- 没有收藏和常用地点时显示对应添加入口

### Q2：失败

- 高德查询失败时保留条件并允许重试
- 做饭规则库没有匹配方案时保留输入并提示减少限制
- 本地数据写入失败时不清空表单，明确提示未保存
- 图片读取、压缩或保存失败时允许继续保存无照片记录
- 本地数据解析失败时不覆盖原始值，界面进入可恢复空状态

### Q3：被引用

- 餐厅和做饭方案创建的饮食记录保存独立标题与摘要
- 取消收藏不删除来源对象
- 删除来源对象不删除已经创建的饮食记录
- 清除全部数据是唯一会同时删除所有对象和照片的操作

### Q4：并发

- 同一页面的主提交按钮在处理时禁用
- 查询和方案生成只接受最后一次操作结果，过期结果不得覆盖当前页面
- 浏览器多标签页写入同一集合时，读取最新版本后按对象编号合并
- 初版无账号，不处理跨设备并发

### Q5：后悔与撤销

- 换一家后允许返回上一家
- 饮食记录删除后提供10秒撤销
- 取消收藏可以立即重新收藏
- 清除全部数据需要二次确认，执行后不可撤销
- 打开外部高德导航后无法撤销外部应用行为

## B3：输入输出链

| 模块 | 输入 | 输出 | 风险处理 |
|---|---|---|---|
| 去哪吃 | 定位、餐次、场合、人数、口味、预算、高德数据 | 推荐餐厅、收藏、预填记录 | 高德失败时保留输入，不伪造真实餐厅 |
| 自己做 | 食材、时间、人数、厨具、口味和补充要求 | 本地规则匹配的做饭方案 | 无匹配时允许减少限制，不生成空步骤 |
| 记一笔 | 手动输入、餐厅快照或做饭方案、可选照片 | 饮食记录和历史列表 | 写入失败不清空输入，照片失败可无图保存 |
| 我的 | 用户输入和其他模块产生的本地数据 | 默认值、常用地点、收藏和历史 | 数据损坏时保留原值并显示恢复提示 |

## B4：正式初版子功能

### 必须实现

1. 四入口应用外壳和移动端导航
2. 保留现有去哪吃推荐、真实餐厅、多图和导航能力
3. 去哪吃餐厅详情、不合适反馈、收藏和快速记一笔
4. 自己做条件输入、本地规则匹配、步骤展示、换方案和快速记一笔
5. 饮食记录新建、编辑、列表、筛选、软删除和撤销
6. 我的个人偏好、常用地点、收藏和数据说明
7. 浏览器本地数据仓库、数据版本和照片存储
8. 四个入口之间的预填和关联跳转
9. 空状态、加载状态、失败状态和防重复提交
10. 不泄露高德Key，不提供医疗和精确营养承诺

### 应该实现

1. 饮食记录支持一张压缩照片
2. 收藏餐厅和做饭方案分组展示
3. 清除全部本地数据
4. 记住用户上一次停留的入口
5. 桌面端保持适合阅读的窄内容区

### 后续版本

1. 登录和云端同步
2. 跨设备数据合并
3. 大模型生成做饭方案
4. 精确营养数据库
5. 多张饮食记录照片

## B5：验收标准

### AC-1：四入口导航

- 前置：用户打开网页
- 操作：依次点击去哪吃、自己做、记一笔、我的
- 期望：每次只显示对应模块；底部当前入口有选中状态；返回之前模块时未提交表单内容仍在
- 关联子功能：必须1、8

### AC-2：刷新恢复入口

- 前置：用户停留在自己做或我的
- 操作：刷新网页
- 期望：页面恢复刷新前的入口；存储值不存在或无效时打开去哪吃
- 关联子功能：应该4

### AC-3：去哪吃现有主流程

- 前置：用户填写有效位置、餐次、场合、人数、口味和预算
- 操作：点击推荐
- 期望：接口成功时展示至少1家符合硬性条件的餐厅；可查看多图、上一家、换一家和高德导航；高德Key不出现在源码和接口响应
- 关联子功能：必须2、10

### AC-4：餐厅详情

- 前置：当前存在餐厅结果
- 操作：点击查看详情
- 期望：信息层展示接口已有的地址、电话、营业时间和照片；缺失字段不显示零值或虚构值；关闭后仍停留在原餐厅
- 关联子功能：必须3

### AC-5：不合适反馈

- 前置：当前存在餐厅结果
- 操作：选择不合适原因并提交
- 期望：本地新增`FeedbackEvent`；当前餐厅进入已跳过状态；界面展示下一家；记录失败不阻塞切换
- 关联子功能：必须3

### AC-6：餐厅收藏

- 前置：当前存在餐厅结果
- 操作：点击收藏，再进入我的收藏
- 期望：餐厅收藏只出现1次并保留名称、地址、图片和高德POI编号；再次点击取消收藏后从列表消失
- 关联子功能：必须3、应该2

### AC-7：餐厅快速记一笔

- 前置：当前存在餐厅结果
- 操作：点击记一笔
- 期望：切换到记录编辑页并预填当前日期、餐次、外出就餐、餐厅名称和餐厅关联；用户保存前可以修改
- 关联子功能：必须3、8

### AC-8：自己做输入校验

- 前置：用户进入自己做
- 操作：食材为空或时间、人数超出范围时点击生成
- 期望：页面指出第一个无效字段，不生成方案；有效范围为至少1项食材、5至240分钟、1至20人
- 关联子功能：必须4、9

### AC-9：生成做饭方案

- 前置：用户填写至少1项食材、有效时间和人数
- 操作：点击生成方案
- 期望：页面显示非空标题、预计耗时、已有材料、缺少材料和至少1个步骤；方案耗时不超过用户填写时间；不显示医疗疗效或精确营养数值
- 关联子功能：必须4、10

### AC-10：更换和收藏做饭方案

- 前置：当前已生成做饭方案
- 操作：点击换一个，再点击收藏
- 期望：存在其他匹配方案时展示不同方案；没有其他方案时明确提示；收藏后在我的做饭方案收藏中出现且不重复
- 关联子功能：必须4、应该2

### AC-11：做饭方案快速记一笔

- 前置：当前已生成做饭方案
- 操作：点击记为吃过
- 期望：切换到记录编辑页并预填当前日期、对应餐次、自己做、方案名称和方案关联
- 关联子功能：必须4、8

### AC-12：手动新建饮食记录

- 前置：用户进入记一笔
- 操作：填写有效日期、餐次、用餐方式、标题后保存
- 期望：记录列表新增一条数据并按用餐时间倒序展示；刷新页面后仍存在
- 关联子功能：必须5、7

### AC-13：记录字段校验

- 前置：用户正在编辑饮食记录
- 操作：标题为空、花费为负数或人数超出1至50时保存
- 期望：页面聚焦第一个无效字段并显示范围提示；不得写入无效记录
- 关联子功能：必须5、9

### AC-14：编辑、删除和撤销

- 前置：列表中存在一条饮食记录
- 操作：修改标题并保存，再删除该记录，随后在10秒内点击撤销
- 期望：修改后列表立即更新；删除后记录暂时消失；撤销后原编号和内容恢复；10秒后未撤销则永久删除关联照片
- 关联子功能：必须5

### AC-15：记录筛选

- 前置：至少存在外出就餐和自己做两种记录
- 操作：按用餐方式筛选
- 期望：列表只显示所选方式；清除筛选后恢复全部记录；空结果显示清除筛选入口
- 关联子功能：必须5

### AC-16：记录照片

- 前置：浏览器支持File API和IndexedDB
- 操作：选择一张图片后保存记录
- 期望：图片被压缩到不超过2MB并与记录关联；列表或详情可以重新显示；图片失败时允许移除图片后保存文字记录
- 关联子功能：应该1、必须7

### AC-17：个人偏好默认值

- 前置：用户在我的设置默认预算60元、默认人数2人和口味偏好
- 操作：新建一次外出用餐需求或做饭方案
- 期望：对应表单使用这些默认值；已经保存的历史需求和记录不被修改
- 关联子功能：必须6

### AC-18：常用地点

- 前置：用户进入我的常用地点
- 操作：新增地点并设为默认，再回到去哪吃
- 期望：地点保存名称、地址和坐标；去哪吃可以一键选用；删除默认地点后默认关联清空
- 关联子功能：必须6

### AC-19：本地存储失败

- 前置：浏览器拒绝或耗尽本地存储
- 操作：保存资料、收藏、方案或饮食记录
- 期望：页面明确显示本次未保存；用户输入不被清空；不得展示保存成功
- 关联子功能：必须7、9

### AC-20：清除全部数据

- 前置：浏览器存在资料、地点、收藏、方案、记录、事件和照片
- 操作：在我的点击清除数据，取消第一次确认，再次操作并确认
- 期望：取消时数据不变；确认后本地存储和IndexedDB数据全部删除，四个模块恢复首次使用空状态
- 关联子功能：应该3

### AC-21：手机和桌面布局

- 前置：分别使用375像素和1440像素宽度打开网页
- 操作：浏览四个模块和主要表单
- 期望：375像素下无横向页面滚动，底部导航可操作；1440像素下内容区限制宽度，不把表单拉满屏幕
- 关联子功能：应该5

### AC-22：公开访问与密钥安全

- 前置：项目部署到公开HTTPS网址并配置服务端高德Key
- 操作：匿名用户直接访问并发起推荐
- 期望：无需安装和登录即可使用；每个浏览器只看到自己的本地数据；页面源码、网络响应和错误信息中不出现高德Key
- 关联子功能：必须2、7、10

### AC-23：手动地点真实解析

- 前置：服务端配置有效高德Key，浏览器定位不可用或用户选择手动输入地点
- 操作：用户输入非空地点并确认
- 期望：前端调用本站服务端地点解析接口，成功后使用高德返回的真实经纬度和可读地址发起推荐；无匹配或接口失败时保留输入并允许修改或重试；前端请求和响应不包含高德Key
- 关联子功能：必须2、10

### AC-24：本地历史

- 前置：用户完成过去哪吃查询、生成过做饭方案或保存过饮食记录
- 操作：刷新网页后进入我的历史
- 期望：分别显示最近的去哪吃需求、做饭方案和饮食记录；单项可以回到对应模块查看或复用；最多保留最近50次用餐需求，清除全部数据后历史为空
- 关联子功能：必须6、7、8
