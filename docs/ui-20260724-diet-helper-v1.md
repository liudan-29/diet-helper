# 饮食小助手正式初版界面设计方案

日期：2026-07-24  
交付对象：code-writer  
范围：去哪吃、自己做、记一笔、我的四入口正式初版

## 1.项目设计语言映射表

### 1.1扫描来源

| 来源 | 结论 |
|---|---|
| `AGENTS.md` | 保留高德真实地点与照片规则；照片没有可靠类型，不虚构门头、环境、菜品标签；前端不得持有或输出高德Key |
| `index.html` | 现有页面是单列编辑式餐饮页面，使用品牌章、刊物标题、偏好筹码、深色餐厅卡 |
| `styles.css` | 原生CSS变量加语义类名，没有框架、预处理器或组件库 |
| `app.js` | 已有表单校验、餐厅卡、多图预加载、横滑切图、上一家、换一家、导航和查询状态 |
| `package.json` | 原生HTML、CSS、JavaScript，无UI库和动画库 |
| 产品结构与AC | 移动端优先、四入口、本地数据、无登录、自己做使用本地规则库 |

项目只有一个可参考页面，没有第二、第三个同类页面。正式初版以现有去哪吃页面为唯一视觉母版，不建立或重构设计系统。

### 1.2现有视觉事实

| 类别 | 项目现状 | 本方案取值规则 |
|---|---|---|
| 主文字 | `--ink:#203128` | 正文、输入文字、浅底图标 |
| 深色主体 | `--deep:#14241c` | 主体卡、主按钮、选中导航 |
| 暖米底 | `--cream:#f3efe4` | 深色卡上的浅文字、页面氛围 |
| 纸张底 | `--paper:#fbf8ef` | 应用壳与主要表面 |
| 苔绿 | `--moss:#6f8b59` | 次级强调、眉题、焦点 |
| 酸橙 | `--lime:#c9dd78` | 核心行动和深底选中态 |
| 橙色 | `--orange:#ed7d43` | 定位提示、警告、错误 |
| 分隔 | `--line:rgba(32,49,40,.14)` | 低对比分隔和输入边界 |
| 次级文字 | `--muted:#758078` | 帮助文字、元信息 |
| 页面外底 | `html`现有浅苔绿背景 | 桌面端应用壳外留白继续沿用 |
| 字体 | `Noto Serif SC`、`DM Mono`、`ZCOOL XiaoWei` | 标题与正文用`Noto Serif SC`，数字和元信息用`DM Mono`，单字章用`ZCOOL XiaoWei` |
| 字号 | `h1`、`h2`、`h3`、`.reason`、`.chip`、`.eyebrow`、`.field-help`现有阶梯 | 新组件按这些现有样式锚点复用，不新增另一套字号比例 |
| 间距 | 页面横向22px；表单卡19px；卡体20至21px；区块间42px；控件间6至9px | 继续使用现有数值锚点，底部导航区域只增加安全区所需留白 |
| 圆角 | 输入9至10px；按钮9至12px；面板17至20px；餐厅卡22px；胶囊999px | 功能层级相同就复用对应圆角 |
| 阴影 | 浅面板低透明绿阴影；深色卡使用更强的深绿阴影 | 只有浮层、餐厅卡和底部导航使用阴影，列表不逐项加阴影 |
| 动效 | `.2s ease`、`.28s ease`、`.45s ease`、`.7s ease` | 控件反馈用`.2s ease`，浮层与结果进入用`.28s`至`.45s ease`，图片缩放沿用`.7s ease` |
| 类名 | 小写英文、连字符、按组件语义命名 | 新类延续`restaurant-card`、`card-actions`、`form-message`风格 |

### 1.3允许补齐的语义层

不改现有token取值，不重命名变量。错误、成功、危险操作仍从现有`--orange`、`--moss`、`--deep`取值，通过图标、边框、文案和结构共同表达，不新增色相。现有字号、间距、圆角和动效没有token，code-writer直接复用上表列出的既有选择器数值，不做全局抽取。

## 2.设计方向

### 2.1Design Thinking

| 问题 | 答案 |
|---|---|
| Purpose | 帮助不想为一顿饭反复权衡的人，在外出、做饭和记录之间快速完成决定；核心用户是手机上单手操作的普通用餐者 |
| Tone | 餐饮刊物式手账，保留纸张、编辑批注、单字印章和深绿餐厅卡，克制、温暖、有食物现场感 |
| Constraints | 原生网页、移动端优先、公开匿名访问、本地存储、无新模型Key、真实餐厅依赖高德、满足键盘和触控可访问性 |
| Differentiation | 餐厅卡的单字章和刊物编号延伸到做饭步骤、记录日期和收藏分组，四个模块像一本持续书写的饮食册 |

### 2.2审美决策

| 原则 | 决策 | 为什么 |
|---|---|---|
| Typography | 继续使用现有三套字体分工，不换系统字体，也不引入新字体 | 项目字体已有明确性格，变更会破坏现有餐厅卡 |
| Color & Theme | 暖米色为大面积背景，深绿承担结构，酸橙只给主行动和选中态，橙色只给警告 | 延续当前页面，避免平均分配颜色 |
| Motion | 动画集中在餐厅或方案结果进入、底部浮层出现、删除撤销三处 | 这些时刻代表状态发生变化，价值高于铺满微动效 |
| Spatial Composition | 保持单列窄壳，标题留白较大，表单紧凑，结果卡形成视觉重心 | 对应手机快速决策场景，也符合现有520px页面 |
| Background & Detail | 继续使用现有纸张底、同心圆装饰、印章和编号，不增加玻璃拟态或通用插画 | 让四个模块具有同一编辑式餐饮语言 |

## 3.信息层级方案

| 层级 | 元素 | 视觉权重 |
|---|---|---|
| 第一层 | 当前模块标题、当前餐厅或方案标题、记录标题、页面主操作 | 标题复用`h1`或`h2`锚点；主操作用`--deep`或`--lime`；字重沿用现有标题和主按钮 |
| 第二层 | 条件表单、餐厅推荐理由、材料与步骤、记录摘要、设置分组 | 复用`.reason`、`.chip`和输入样式；主文字用`--ink`，深底用`--cream` |
| 第三层 | 数据来源、字数与范围提示、日期和费用、空状态说明、本地数据说明 | 复用`.eyebrow`、`.data-note`和`.field-help`；使用`--muted`或`--moss` |

信息层级同时依靠字号、字重和颜色。图标不单独承担含义，所有关键操作保留文字标签或可访问名称。

## 4.布局结构

### 4.1应用外壳

```text
┌────────────────────────────┐
│ 品牌章  当前模块标题   上下文操作 │
├────────────────────────────┤
│                            │
│ 当前模块内容，单列滚动          │
│                            │
│ 为底部导航预留安全区            │
├────────────────────────────┤
│ 去哪吃  自己做  记一笔  我的    │
└────────────────────────────┘
```

- 应用壳继续使用现有最大宽度520px，居中显示
- 375px下页面横向内边距沿用22px，无横向滚动
- 主模块顶部显示品牌章和模块标题；进入详情、编辑、设置子页后左侧改为返回，标题改为子页名称
- 底部导航固定在视口底部，宽度与应用壳一致，叠加底部安全区；内容区补足导航高度加安全区
- 切换四入口时保留每个模块的表单草稿、结果位置、筛选条件和滚动位置
- 首次进入打开去哪吃；刷新恢复有效入口，无效值回退去哪吃

### 4.2断点行为

| 宽度 | 行为 |
|---|---|
| 320至520px | 单列；底部导航固定；长按钮文案不折行；表单标签沿用73px加内容列，窄于360px时标签改为上下排列 |
| 521px及以上 | 应用壳固定最大宽度520px并居中，沿用现有外部背景和壳阴影；表单不拉宽，不改双栏 |
| 横屏且高度不足 | 底部浮层最大高度限制在可视区内，内容滚动，标题和主操作分别吸顶、吸底 |

### 4.3浮层模式

- 餐厅详情、不合适反馈、删除确认和清除数据确认在手机使用底部浮层
- 桌面端仍在520px应用壳内居中呈现，不扩展成宽屏弹窗
- 记录新建编辑、个人偏好和常用地点编辑内容较长，使用模块内全页层，不塞进底部浮层

## 5.公共组件规格

### 5.1状态基线

以下状态适用于所有按钮、筹码、输入和可点击行，组件另有说明时以组件说明为准。

| 状态 | 规格 |
|---|---|
| 默认 | 使用现有组件颜色和圆角，触控目标不小于44×44px |
| hover | 只在支持悬停的设备启用；颜色过渡沿用`.2s ease`，不通过位移造成布局抖动 |
| active | 颜色加深或轻微压缩，持续沿用`.2s ease`；不能只靠缩放表达 |
| disabled | 降低对比度并移除指针反馈；保留可读标签；处理中按钮改为当前动作文字 |
| focus-visible | 使用`--moss`焦点边与现有三层焦点环模式，不能去掉键盘焦点 |
| error | 输入边界和提示使用`--orange`，同时显示警示图标、具体错误和`aria-describedby` |

### 5.2组件清单

| 名称 | 类型 | 视觉规格 | 四态与内容约束 |
|---|---|---|---|
| 顶部栏 | 现有`.topbar`变体 | 品牌章、模块标题、最多一个上下文操作；纸张底 | 默认显示模块名；子页显示返回；标题超过10字单行省略；无disabled |
| 底部导航 | 新增公共组件 | 四等分，纸张底加轻阴影；当前项使用深绿底和酸橙图标文字 | hover用浅表面差；active为`--deep`加`--lime`；disabled不出现；使用`nav`和`aria-current=page` |
| 主按钮 | 复用`.recommend-button`、`.primary-button` | 酸橙底深绿字或深绿底暖米字，当前页面只设一个主行动 | hover提高对比；active轻压；disabled沿用现有等待态；标签最长10字 |
| 次按钮 | 复用`.secondary-button` | 透明或纸张底、低对比分隔 | hover使用浅背景；active边界加深；disabled降低对比；文字最长8字 |
| 图标按钮 | 新增公共variant | 收藏、关闭、更多使用线性图标，44px触控区，不使用无文字含义的emoji | 默认图标加可访问名称；收藏active用酸橙填充；disabled保留原因提示 |
| 单选筹码 | 复用`.chip` | 胶囊、正文衬线字体 | active沿用深绿底酸橙字；disabled不可点击；超长文本单行省略，最多12字 |
| 多选筹码 | 复用`.chip`变体 | 与单选外观一致，选中时带勾图标 | hover、active、disabled同上；不限与具体选项互斥 |
| 文本与数字输入 | 复用现有输入 | 纸张浅表面、分隔边、焦点环 | error必须边框加图标加文字；disabled仅用于系统预填不可改字段；数字使用`DM Mono`并右对齐 |
| 文本域 | 新增输入variant | 延续输入圆角和字体，可显示字数 | 最小3行，内容区可增高；食材支持逗号和换行；中文使用`overflow-wrap:anywhere`，不用`word-break:break-all` |
| 分组标题 | 复用`.eyebrow`加`h2` | 眉题为苔绿等宽字，主标题为衬线字 | 无交互态；主标题最多2行 |
| 信息行 | 新增公共组件 | 左侧图标和标签，右侧值；主要靠间距分组，不逐行加边框 | 点击行hover出现浅底；active加深；disabled值显示不可用原因；值最多2行 |
| 空状态 | 新增公共组件 | 单字章、短标题、说明、一个主行动；不用通用插画卡 | 文案为标题12字内、说明两行内；筛选空状态必须附清除筛选 |
| 状态横幅 | 新增公共组件 | 左侧状态图标，右侧标题和说明，可带一个重试行动 | 成功用`--moss`，警告与错误用`--orange`；不可只变文字颜色 |
| 底部浮层 | 新增公共组件 | 纸张底、顶部标题与关闭、底部主行动；圆角沿用面板级 | 打开和关闭用`.28s ease`纵向过渡；背景遮罩点击是否关闭按风险决定；危险确认不允许误触遮罩关闭 |
| 轻提示条 | 新增公共组件 | 贴近底部导航上方，深绿底暖米字，可带撤销按钮 | 进入、退出用`.28s ease`；普通提示自动消失，删除撤销固定10秒并有可见倒计时 |
| 加载占位 | 新增公共variant | 沿用纸张和深绿层级，不使用与真实照片相似的假图 | 主按钮显示动作；照片保持当前实景图直到目标图就绪；无图才显示现有渐变占位 |

## 6.去哪吃

### 6.1需求表单

- 首次状态保留现有大标题、编辑式说明和`.picker`表单
- 地点置于表单第一项，显示当前位置或常用地点；定位按钮继续使用橙色圆点
- 常用地点存在时，在地点下方显示最多3个快捷筹码，末项为管理地点
- 餐次、场合、人数、口味、自定义要求和预算沿用现有字段顺序、范围与校验
- 主行动继续使用给我挑一家；查询中标签改为正在查询附近餐厅并筛选，禁止重复提交
- 已有结果时大标题区域收拢为当前条件摘要，点击修改条件回到完整表单，餐厅卡保持原结果直到新查询成功

为什么：现有去哪吃流程已验证，正式初版只补充信息和行动层，不改变决策主线。

### 6.2餐厅结果卡

- 继续使用现有深绿餐厅卡、实景照片、单字章、推荐理由、评分、人均、距离、营业信息和编号
- 标题行右上放收藏图标；评分保留原位置，收藏图标与评分不得重叠
- 查看详情作为卡内明确文字入口，放在推荐理由之后
- 原有三格行动保留上一家、换一家、去这里
- 卡外增加一条安静行动栏：不合适、记一笔；记一笔视觉权重高于不合适，低于去这里
- 高德照片只显示高德实景和序号，不显示门头、环境、菜品等类型标签
- 名称最多2行；品类、距离、人均单行省略；推荐理由最多3行；标签最多4个
- 无结果显示修改条件和扩大范围行动；高德失败不显示演示餐厅，保留条件并提供重试

为什么：行动分两层避免一张卡塞入7个同权按钮，仍保留现有卡片编辑感。

### 6.3餐厅详情

移动端底部浮层结构：

1.标题、收藏、关闭
2.复用同一组照片轮播
3.品类、评分、人均、距离摘要
4.地址、电话、营业时间信息行
5.数据来源与抓取说明
6.固定底部的去这里和记一笔

- 字段缺失时整行隐藏，不显示未知、0、空字符串或虚构内容
- 关闭后回到原餐厅、原照片序号和原页面滚动位置
- 电话有值时可点击拨号；地址仅展示，不把不可靠字段当导航目标
- 照片加载失败后移除该URL，全部失败时回到现有渐变占位，且占位不计入总数

### 6.4不合适反馈

- 使用单选列表：餐次不符、场合不符、超预算、距离太远、已打烊、不喜欢品类、其他
- 选其他后显示最长80字的补充输入
- 主行动为提交并看下一家，次行动为取消
- 提交成功关闭浮层、记录跳过并展示下一家
- 记录事件失败时仍切换下一家，同时用轻提示说明反馈未保存，不阻塞选择
- 最后一家提交后回到第一家并标注已看完一轮，不显示空白卡

### 6.5收藏与快速记一笔

- 收藏点击后立即切换图标和可访问名称，写入失败时恢复原状态并提示本次未保存
- 同一高德POI只保留一条收藏
- 点击记一笔切换到记录编辑页，预填当前日期、当前餐次、外出就餐、餐厅名和关联编号
- 返回去哪吃时恢复原餐厅、表单和滚动位置

## 7.自己做

### 7.1条件表单

| 字段 | 规格 |
|---|---|
| 已有食材 | 必填文本域，支持逗号和换行；失焦后可显示可删除食材筹码；至少1项 |
| 可用时间 | 数字输入，范围5至240分钟；提供15、30、45、60分钟快捷筹码，最终以数字输入值为准 |
| 用餐人数 | 数字输入，范围1至20，默认读取个人偏好 |
| 可用厨具 | 多选筹码，选项由本地规则库提供；没有选择表示不限定 |
| 口味偏好 | 多选筹码，默认读取个人偏好，可在本次修改 |
| 补充要求 | 最长200字文本域，附不提供医疗建议和精确营养计算的短说明 |

- 主行动为生成方案
- 无效时聚焦第一个字段，错误使用边框、图标和范围文案
- 生成中保留所有输入，只接受最后一次生成结果
- 没有匹配时显示减少限制、修改条件，不生成空标题或空步骤

### 7.2方案结果

- 结果使用纸张食谱页，不照搬三等分数据卡
- 顶部显示单字章、方案名、预计耗时和人数
- 材料分为已有材料、还需准备，两组使用不同标题，不增加新色相；缺少材料为空时显示无需额外准备
- 步骤使用左侧等宽序号和右侧正文，序号延续单字章轮廓
- 注意事项放在末尾浅面板，只写操作与食品安全常识，不写疗效或精确营养数值
- 底部主行动为记为吃过，次行动为换一个，收藏为图标按钮
- 换方案时保留条件；有其他匹配项则结果卡用`.45s ease`进入；无其他项时保留当前方案并提示没有更多匹配方案
- 收藏和记录写入失败时保留当前结果，不展示成功态

### 7.3空、加载、错误

| 状态 | 表现 |
|---|---|

## 8.记一笔

### 8.1列表与筛选

- 顶部为模块标题、记录数量和新建按钮
- 筛选第一行显示全部、外出就餐、自己做、外卖、其他筹码；日期筛选放在可展开筛选层
- 记录按日期倒序，同日按餐次起始时间倒序，再按更新时间倒序
- 列表项显示日期与餐次、方式、标题、花费、感受，可选照片缩略图
- 日期和金额用`DM Mono`；金额右对齐；无花费时整项隐藏，不显示0
- 标题最多2行；吃过内容最多2行；备注只在详情展示
- 点击列表项进入详情，编辑作为详情页明确行动
- 全局无记录显示新建第一条记录；筛选无结果显示清除筛选

### 8.2新建与编辑

字段顺序：

1.用餐日期、餐次
2.用餐方式
3.餐厅或菜名
4.吃了什么
5.花费、同行人数
6.感受
7.备注
8.一张照片

- 日期、餐次、方式、标题是核心输入；标题必填
- 花费范围0至100000，人数范围1至50；数字右对齐
- 感受使用很满意、还可以、不太好三项带文字的单选筹码，不只用表情
- 照片区支持选择、预览、替换和移除；压缩或保存失败时显示图标加说明，允许移除照片后保存文字记录
- 从餐厅或做饭方案进入时，在标题上方显示来源提示，所有预填字段仍可修改
- 保存处理中禁用主按钮；本地写入失败保留全部输入，明确显示本次未保存
- 离开有未保存修改的编辑页时弹出放弃修改确认

### 8.3详情、删除与撤销

- 详情按编辑表单同顺序展示完整信息，缺失项隐藏
- 页面底部显示编辑和删除，删除使用`--orange`边界加删除图标，不单靠颜色
- 删除前底部确认浮层说明记录会先移出列表，并提供取消和删除
- 删除后回到列表，轻提示条显示已删除、撤销和10秒倒计时
- 10秒内撤销恢复原编号和内容；超时后永久清理关联照片
- 轻提示条可由键盘聚焦，倒计时结束前不因页面滚动消失

- 显示当前浏览器、本地保存、不会跨设备同步三条事实
- 可显示资料、地点、收藏、方案、记录的数量，不展示虚假的云端同步状态
- 清除全部数据使用独立危险区，按钮带删除图标和明确文案
- 第一次操作打开不可逆确认浮层；取消不改变数据；确认后按钮进入正在清除
- 成功后清除结构化数据和IndexedDB照片，四模块恢复首次状态
- 清除失败时列出未完成，不声称成功；损坏数据读取失败时显示恢复空状态说明，并保留原始备份

## 10.交互与动效规范

| 场景 | 动效 | 时长与缓动 |
|---|---|---|
| 四入口切换 | 内容淡入，不横向滑屏，避免误解为层级返回 | 复用`.2s ease` |
| 餐厅、方案结果更换 | 旧内容保持到新内容可用，新卡轻微上移淡入 | 复用`.45s ease` |

## 12.工程正确性自检

### 12.1可访问性与输入

- 所有输入有可见标签，必填、范围和错误通过文本说明
- 错误聚焦第一个无效字段，错误不只使用红色或橙色文字
- 键盘可操作全部筹码、导航、轮播、浮层、收藏和撤销
- 底部导航、图标按钮、轮播按钮触控目标不小于44×44px
- 浮层具有标题关联、焦点圈定、Escape关闭和关闭后焦点归还；危险确认不因遮罩误触关闭
- 状态消息使用合适的`status`或`alert`语义，普通更新不反复打断读屏

### 12.2导航与响应式

- 四入口使用导航语义和当前页状态；浏览器返回优先关闭浮层或返回子页，不直接退出应用
- 375px下无横向滚动；1440px下壳宽仍限制为520px
- 底部导航避让安全区；内容和轻提示条不被导航遮挡
- 中文标题和地址允许自然换行，长英文URL和连续字符可断行，不使用全局强制断字

### 12.3图片、装饰和动效

- 餐厅照片提供餐厅名加序号的替代文本；纯装饰圆环、印章背景和分隔图形对读屏隐藏
- 装饰同心圆不覆盖输入、文字和触控区，保持`pointer-events:none`
- 高德照片不虚构类型标签；无图占位不计入照片总数
- 用户上传照片预览有移除和替换操作，失败时仍可保存文字记录
- 支持减少动态效果，动画不会阻塞主要操作

### 12.4数据与反馈

- 主提交处理中防重复；异步结果只接受最后一次请求
- 本地写入成功前不清空表单，不展示保存成功
- 多标签页写入按对象编号合并，冲突后刷新当前列表
- 清除数据二次确认且不可撤销；删除记录提供10秒撤销
- 外部高德导航明确离开当前页面，并使用安全的新窗口行为
- 本项目没有图表，图表可访问性条目不适用
