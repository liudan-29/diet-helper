# 饮食小助手

## 这是干嘛的

一个网页版饮食决策工具：用户选择餐次、用餐场合、同行人数、口味和预算后，获得附近合适餐厅的推荐与导航入口。当前已接入高德 MCP 获取真实数据。

## 怎么跑

需要Node.js 20或更高版本。首次运行安装依赖：

```powershell
npm install
npm start
```

访问 `http://localhost:4173`。

复制 `.env.example` 为 `.env`，填入高德开放平台中“Web服务”类型的Key：

```text
AMAP_MCP_KEY=你的Key
```

没有配置Key时，项目自动使用演示餐厅数据；配置后，服务端通过高德MCP周边搜索查询真实餐厅。首次筛选不足5家时，会自动更换关键词并将范围逐步扩大到2公里、3公里，合并去重后最多返回8家；餐次、场合和预算等硬性条件不会为了凑数量而放宽。

推荐先检查餐厅营业时间是否覆盖用户选择的餐次。午餐默认按11:00至14:30判断，早餐专营店或只在早餐时段营业的餐厅不会进入午餐排序。营业时间缺失时，才使用餐厅名称、类别和当前营业状态兜底。

可以单独验证高德 MCP 是否连通：

```powershell
npm run check:amap
```

这个命令只输出连接结果和餐厅摘要，不会输出Key。

## 备注

- 当前已包含Node服务端、用餐条件校验、餐厅筛选排序与高德MCP客户端。周边搜索后会继续查询餐厅详情，以补齐坐标、评分、人均价格、营业时间和真实照片；照片缺失或加载失败时使用渐变占位图。
- 场合使用预设加自定义输入；同行人数直接填写；口味支持多选。其他要求可以识别面馆、火锅、烤肉等餐厅类型，菜品级忌口、过敏和医疗要求仍需向餐厅确认。
- 高德和模型服务密钥仅配置在本地 `.env` 文件或部署平台环境变量中，不能提交到仓库。
- 第一版不做原生 APP、微信小程序、支付、社交和医疗建议。
- MVP 暂时只展示“去哪吃”，不代表其他功能被取消。完整功能与暂缓原因见 `docs/product-roadmap.md`。
